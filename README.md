# Marketing Analytics Datathon

An end-to-end B2B marketing analytics case study that turns eight CRM and marketing exports into validated marts, the preserved Revenue Command Center dashboard, and a browser-based decision brief.

## Executive answer

The current schema-v3 snapshot contains 3,245 canonical, non-deleted opportunities: 2,834 are resolved (won, lost or discontinued) and 1,070 are won. Recorded amount across all deals is $24,876,699.31, including closed-lost deals; open pipeline is $7,026,136.93. Recorded won amount is $5,419,871.93, but 699 of the 1,070 wins have a zero amount, and those wins carry $3,447,433.79 of monthly recurring revenue (MRR) in a separate field, 94% of it on existing-customer deals. MRR is reported beside amount, never added to it.

A deal counts as acquisition when its account had no earlier won deal; this classifies every year, including 2023–24, where the CRM type field is blank. Referral leads recorded new-logo won amount across 2018–2024. In 2023–24 new-logo deals, marketing-sourced opportunities convert lowest: 10.2% of resolved deals won, against 26.8% for referral, while marketing supplied 382 of 1,192 new-logo opportunities. Channel rankings are descriptive and do not establish incremental channel value.

The recommendation is to fix marketing-sourced conversion before adding volume, protect referral, record contract value on every win, and run controlled creative and account-coverage tests before expanding spend. Eligible 365-day marketing touches link to 684 opportunities, including 127 wins; email, web and 6sense logs cover 2024 only, so those links are read against the 1,191 opportunities created in 2024 (57% linked), and about 79% of usable touches are 6sense ad impressions aimed at in-market accounts. The current ICP audience has 2,034 eligible domains. Under the default 5% baseline and 2 percentage-point absolute-lift assumption, a two-arm test needs 4,426 accounts, so the current audience is too small for that scenario. Only five ads have complete format, message, and tone labels. A calendar-only win-probability model was withdrawn because its holdout was near chance and predicted no wins.

## Canonical sources and generated copies

- `frontend/src/` contains the React dashboard and browser-presentation source.
- `frontend/public/` contains canonical static inputs, including the schema-v3 evidence contract and the legacy dashboard data/context inputs.
- `outputs/` contains generated analysis workbooks and the legacy Plotly dashboard archive. The legacy dashboard is preserved as a full-analysis view.
- `public/` is the generated deployment directory. It contains the production React build and copied static data; edit source files under `frontend/` and rebuild rather than editing generated copies directly.
- `data/cleaned/` and `data/integrated/` contain generated cleaned datasets and analysis marts.
- The two root-level project playbook PDFs are supporting process references, not runtime dependencies or current presentation deliverables.

## Reproduce the analysis

Requirements: Python 3.11, Node.js 20, and the supplied source files under `Analytics Case Study/`.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
npm ci
python run_pipeline.py
```

macOS or Linux:

```bash
source .venv/bin/activate
pip install -r requirements.txt
npm ci
python run_pipeline.py
```

The default runner executes, in order:

1. `01_data_cleaning.py`
2. `02_data_integration.py`
3. `03_analysis.py`
4. `03b_attribution.py`
5. `03c_advanced_analytics.py`
6. `03d_case_analysis.py` to build the schema-v3 evidence contract
7. `04_html_dashboard.py` to regenerate the legacy Plotly archive
8. `04_react_dashboard.py` to export dashboard data and build the production React dashboard
9. `06_validate_metrics.py`

`python run_pipeline.py --dry-run` prints this sequence without running it. The runner does not invoke the historical PPTX generator.

## Validate before sharing

CI regenerates the full analytics pipeline from supplied source files, builds the browser artifact, runs Python and frontend regressions, and validates public fields, schema/reference essentials, numerical reconciliation and Vite imported/lazy assets. Pages deployment depends on that successful job and consumes its uploaded bytes. The separate deployment workflow cannot publish committed artifacts. No workflow has been run remotely in this repair.

Run the release checks locally:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
npm run typecheck
npm run build
python analytics_case_study/06_validate_metrics.py
```

Serve the compiled application with Flask:

```bash
python app.py
```

Open `http://localhost:8050/` for the dashboard, `http://localhost:8050/#present/main-01` for the findings deck, or `http://localhost:8050/full-analysis` for the preserved Plotly archive. Use `npm run dev` for frontend development.

Render is configured for the multi-stage `Dockerfile`: regeneration, build and regression/semantic checks must pass before the runtime image can be created. The final image copies only the compiled public artifact and server helpers; source workbooks and private marts stay in the build stage. This configuration is locally authored and has not been deployed or tested on Render.

## Reproducibility and evidence limits

`constraints.txt` captures the local Python 3.11.9 dependency versions (2026-10-03). `requirements.txt` applies those constraints; Node uses `package-lock.json`. Upgrade constraints in a dedicated change, regenerate all artifacts, run semantic/model/interaction regressions, compare reconciled totals and model diagnostics, and record any tolerance change explicitly. A captured environment is not a clean-install reproduction receipt. `outputs/run_metadata.json` records Python/package versions, input file hashes and run times; source observation dates remain separate from build time.

No scheduled production freshness policy has been approved. Supplied files are historical extracts. Schema or date changes must be investigated against source coverage; a newer generated_at alone never proves fresher source data.

Public contracts contain aggregate score bins and journey totals, not individual opportunity IDs, names, stages or commercial amounts. `artifact_safety.py` enforces a private-field denylist and build/readiness checks. This reduces unnecessary exposure; it does not establish publication rights or repository visibility. Existing source files/history remain untouched.

Pending external evidence: **F55** currency authority and official competition rubric; **F56** publication/privacy rights, repository visibility and last verified live deployment; **F57** authoritative missing opportunity amounts; **F58** sent/delivered email records and denominator definitions. The dollar symbol is a display convention; no verified USD authority is asserted and source amounts are not converted or backfilled. **F59** private account/opportunity/touch drill-through remains future governed work requiring access rules, retention and approved identifiers before implementation. It is excluded from public artifacts.

The existing PPTX is a historical archive (retired population/model/budget definitions), not a current deliverable. Both Python and direct JavaScript historical generation are disabled. Its former special Codex artifact runtime is not an ordinary npm dependency; use the current browser presentation instead.
