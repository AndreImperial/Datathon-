# Revenue Command Center — Marketing Analytics Datathon

An end-to-end B2B marketing analytics case study. Eight CRM and marketing exports become validated data marts, an interactive dashboard and an 18-minute browser presentation for a CMO.

**The big idea:** Fix conversion before buying volume. Prove reach before scaling spend.

- [Live dashboard](https://marketing-analytics-dashboard-saoj.onrender.com/)
- [Live presentation, first slide](https://marketing-analytics-dashboard-saoj.onrender.com/#present/main-01)

## Executive answer

The snapshot contains 3,245 canonical, non-deleted opportunities: 2,834 are resolved (won, lost or discontinued) and 1,070 are won. Recorded amount across all deals is $24,876,699.31, including closed-lost deals; open pipeline is $7,026,136.93. Recorded won amount is $5,419,871.93, but 699 of the 1,070 wins have a zero amount, and those wins carry $3,447,433.79 of monthly recurring revenue (MRR) in a separate field, 94% of it on existing-customer deals. MRR is reported beside amount, never added to it.

A deal counts as acquisition when its account had no earlier won deal; this classifies every year, including 2023–24, where the CRM type field is blank. Referral leads recorded new-logo won amount across 2018–2024. In 2023–24 new-logo deals, marketing-sourced opportunities convert lowest: 10.2% of resolved deals won, against 26.8% for referral, while marketing supplied 382 of 1,192 new-logo opportunities. Channel rankings are descriptive and do not establish incremental channel value.

The recommendation: fix marketing-sourced conversion before adding volume, protect referral, record contract value on every win, and run a controlled account-coverage test before expanding spend. Eligible 365-day marketing touches link to 684 opportunities (127 wins); email, web and 6sense logs cover 2024 only, so those links are read against the 1,191 opportunities created in 2024 (57% linked), and about 79% of usable touches are 6sense ad impressions aimed at in-market accounts. The ICP audience has 2,034 eligible domains, while the default 5% baseline / +2 percentage-point test needs 4,426 accounts. Only five ads have complete creative labels. A calendar-only win-probability model was withdrawn because its holdout was near chance and predicted no wins.

## Reproduce the analysis

Requirements: Python 3.11 and Node.js 20 or later. The source files are in `data/raw/`.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
npm ci
python run_pipeline.py
```

macOS or Linux:

```bash
source .venv/bin/activate
pip install -r requirements.txt
npm ci
python run_pipeline.py
```

The runner executes, in order:

1. `01_data_cleaning.py`
2. `02_data_integration.py`
3. `03_analysis.py`
4. `03b_attribution.py`
5. `03c_advanced_analytics.py`
6. `03d_case_analysis.py` — the schema-v3 evidence contract behind the presentation
7. `04_html_dashboard.py` — the legacy Plotly archive
8. `04_react_dashboard.py` — dashboard data export and production React build
9. `06_validate_metrics.py` — contract validation

`python run_pipeline.py --dry-run` prints the sequence without running it.

## Validate and serve

```bash
python -m unittest discover -s tests
npm test
npm run typecheck
npm run build
python analytics_case_study/06_validate_metrics.py
```

```bash
python app.py
```

Open `http://localhost:8050/` for the dashboard, `http://localhost:8050/#present/main-01` for the presentation, or `http://localhost:8050/full-analysis` for the Plotly archive. Use `npm run dev` for frontend development.

On every push to `main`, CI regenerates the full pipeline from `data/raw/`, runs the Python and frontend tests and the contract validator, and deploys the exact validated build to GitHub Pages. Render builds the multi-stage `Dockerfile`, whose runtime image contains only the compiled public build and the server helpers.

## Reproducibility and evidence limits

`constraints.txt` pins the Python 3.11 dependency versions and `requirements.txt` applies them; Node uses `package-lock.json`. A clean Python 3.11 install from these files has been verified, and two pipeline runs produce identical contract values. `outputs/run_metadata.json` records package versions, input file hashes and run times.

Public contracts contain aggregates only: no opportunity IDs, names, stages or individual amounts. `artifact_safety.py` enforces that denylist. It does not establish publication rights.

Open items that need the data owner: currency authority (the `$` is a display convention; amounts are not converted), publication and privacy rights, authoritative values for zero-amount wins, sent/delivered email records for send-based rates, and governed access for any account-level drill-through.
